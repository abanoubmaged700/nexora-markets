# NEXORA Markets — سياق المشروع

آخر تدقيق: 25 أكتوبر 2026. المرجع الحالي: [تقرير تدقيق التكامل](audit/INTEGRATION_AUDIT.md). الوثائق الأقدم محفوظة في audit/previous-docs للتاريخ فقط، وقد تتضمن حالة سبقت اختبار Telegram واستلام التطبيق.

المهمة الحالية تدقيق التكامل والجاهزية، لا إعادة بناء المشروع أو توسيع نطاقه. الهوية: محتوى مالي عربي تعليمي موثّق، والموافقة التحريرية بشرية.

## الحالة المثبتة

- استُلمت حزمة تطبيق Google AI Studio وفُحص server.ts وتعريفات الوكلاء والتخزين ومخطط n8n. توجد ستة تعريفات بمطالبات ومخططات، مرتبطة بمسار SDK مشترك. جودة تشغيلها الحي غير مختبرة.
- سجل n8n الفعلي يتضمن اختبار Telegram الخاص الناجح: التنفيذان 33 و34، message_id 4 و5. هذا لا يثبت نشر الأخبار أو جاهزية التطبيق.
- لقطة قاعدة n8n المحلية: عشرة Workflows، واحد فقط لـ NEXORA وهو اختبار الاتصال. News Engine والوكلاء الستة غير مثبتة كمسار منشور في هذه القاعدة.
- جدول NEXORA_News_Log يحتوي عشرة أعمدة؛ تنقصه verification_status وgemini_input_tokens وgemini_output_tokens وgemini_model. صفوفه صفر.
- قاعدة SQLite المرفقة بالتطبيق فارغة. آخر فحص اتصال محلي للمنفذين 5678 و3000 رُفض؛ سبب توقف الخدمة الحالي غير محسوم.
- 12 اختبارًا معزولًا لكود التطبيق: 3 PASS و9 FAIL، مع بدائل وهمية للشبكة والتخزين. هذه نتائج منطق برمجي وليست اختبارًا حيًا شاملًا.
- لا يوجد إثبات للمسار Economic News → Content Creator → Human Approval → Telegram Publish من البداية للنهاية.

## أول عائق

الموافقة غير محمية بهوية وصلاحية المراجع، ويمكن لمخرجات النموذج الاحتفاظ بحالة APPROVED. يجب إصلاح سلطة الموافقة وحالة المسودة في الخادم قبل إكمال النشر. مخطط n8n المرفق يفتقد سلسلة Content ومعالجة قرار الموافقة والناشر النهائي.

## القيود

لا أسرار في المحادثة أو التصديرات. لا نشر عام أو تنفيذ صفقات ضمن التدقيق. لا استدعاءات Gemini مدفوعة أُجريت في هذا التدقيق. الرمز السابق الذي ظهر في المحادثة أفاد المستخدم بتدويره؛ لا يعاد استخدامه. فحص أنماط الرموز بالحزمة نظيف، لكن يوجد سر Webhook افتراضي مكتوب بالكود يجب إزالته.

Notion: نستخدم مهمة News Engine الحالية وسجل Workflow Library الحالي؛ لا مهام مكررة. تقرير التدقيق هو المرجع لأدلة الاختبار والقيود.
